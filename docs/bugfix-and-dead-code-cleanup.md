# Bug 修复与未使用代码清理

2026-09-29，仓库 `E:\I-am-home`。本轮按代码审查结果修复，不新增产品功能、不开发适老化、不启用真实短信，不删除用户数据。

## 七类问题

1. **暂停后误恢复**：页面存储失败原本会留下旧的“未暂停”数据，重启时自动开启。现在原生在停止时原子保存 `userPaused`，启动预检先接纳原生暂停；自动开始不能清除该标记，只有明确恢复可以。失败的恢复权限检查不清除暂停。页面保存失败仍会提示，不假称保存成功。
2. **围栏快速改回原值丢失**：原来已同步 A、正在写 B 时，再要求 A 会被旧的去重判断跳过。现在有在途写入时不按历史成功值去重，B 成功或失败后都继续写入最终的 A。
3. **地点失败重试重复添加**：每个添加草稿使用稳定 ID，重试更新同一条记录；达到第 20 个地点时仍可重试该草稿。同步前重新读取当前配置，避免等待保存期间的新编辑被旧快照覆盖。
4. **后台刷新关闭仍显示正常**：正常状态展示与自动/明确启动的权限检查统一要求后台刷新可用；已运行的守护不会因页面刷新被反复重启，但会显示能力受限。
5. **调时后拒绝新位置/冻结无活动检查**：恢复、位置回调、活动处理及无活动检查会协调未来锚点，丢弃旧时钟下的未来 GPS 比较锚点，重设无活动计时。活动中的告警不因这次协调自动解除，需新活动/回家证据；现有休息时段规则继续有效。
6. **系统接受短信后结果保存失败引发重发**：发送结果和结果持久化分开捕获错误。存储错误向外报告，不再次当作发送失败完成操作；发送结果未落盘时保持不明结果策略，租约到期后失败而非自动重试。已 accepted 的操作也不能被迟到的失败回调降级。
7. **同时排队的多个风险绕过冷却**：除了入队时计算，还在真正开始每次发送前按同联系人其他风险的实际尝试时间复查冷却。不同联系人互不阻塞，同一风险仍使用原有重试间隔，未到发送时机不消耗尝试次数。

## 接口与存储兼容

- `getCurrentStatus()` 新增必需布尔值 `isGuardianPaused`。旧原生包缺少该字段会在预检失败，不能继续配置或自动开始。
- `startGuardian(config, resumePaused)`：自动启动为 false，用户明确恢复为 true；Swift 与 Objective-C 桥接同步更新。
- JS schema v4 / 原生 v6 不变。原生存储新增可选读取字段 `userPaused`，旧文件缺少时为 false，既有 JS 暂停意图仍参与保护；不清空联系人、地点或历史来完成升级。
- 清除完成后原生和页面都保持暂停。新 JS 必须与新原生一起构建；不能靠仅替换 JS 包验证本轮修复。
