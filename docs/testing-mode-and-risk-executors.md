# 模式分离与原生风险执行器

更新：2026-09-28。代码位于 Windows 仓库 E:\I-am-home。

## 已实现与验证范围

测试/正式模式、低电量、长时间无可信位置的代码已接入。Windows 已通过类型检查、79 项 Node/React 测试和 iOS JavaScript 打包。iOS target 和测试 target 已加入新的 GuardianRiskDetector.swift；Swift 测试源从 21 项增至 31 项，当前机器没有 Swift/Xcode，本轮未运行 XCTest、原生编译或 iPhone 安装。

Critical Messaging 构建开关仍为 false，未添加 entitlement；两个执行器可以记录本机风险和准备通知操作，不能据此宣称家人会收到短信。

## 模式与设置

- “我的 → 守护模式/守护时间”可切换测试、正式模式，切换需要用户确认。
- 新设备和旧数据升级后使用测试模式。地点、家人、暂停意图、原有停留阈值及历史记录均保留。
- 测试模式两个时间阈值允许 1–240 分钟，有“使用 1 分钟测试阈值”入口。新原生事件含 isTest，标题带“测试”；准备的短信也有测试标识。
- 正式模式阈值允许 15–240 分钟。默认停留和位置中断均为 120 分钟；从测试切到正式时，小于 15 分钟的值恢复为 120 分钟。15 分钟是本轮用于隔离短时测试的工程限制，不表示已完成正式产品的误报/漏报校准。
- 进入正式模式需真实“家”、至少一位家人、始终定位、精确位置、后台 App 刷新和围栏同步。原生再次校验，不能仅改 JS 文案绕过。
- JS 按顺序传递完整规则快照，原生一次保存模式、阈值和守护时段。同一配置重放不会重新计时；模式/规则变化会结束旧风险周期、取消未发送操作，再开始检查。实际已提交的短信不能撤回。
- 测试告警仅在本机记录；即使以后启用短信 entitlement，测试模式和 isTest 操作仍不能进入自动发送。人工快捷指令测试保留原有确认弹窗和测试正文。

## 低电量

沿用产品既定规则：确认家外、已知电量低于 20%、明确未充电时触发一次 LOW_BATTERY。未知电量（包括系统返回 -1）、未知充电状态和在家不会新建该风险。

连接充电、电量恢复到至少 20% 或回家后生成 BATTERY_RECOVERED，并取消此风险未发送的短信。解除后重新满足条件可以产生新一轮；不重复上报同一轮，不解除其他位置风险或主动 SOS。

## 无可信位置

只有现有定位策略接受的 GPS 样本能更新 lastTrustedLocationAt。围栏事件、步数、运动识别、Visit 和通知操作都不能伪装为新的 GPS 样本。

在每日守护时段内、确认家外或尚不能确认是否在家时，从当前检查周期开始时间和最近可信位置时间中较晚者累计。超过位置中断阈值生成一次 LOCATION_LOST：

| 原因 | 条件 |
| --- | --- |
| locationStale | 长期没有新的可信位置 |
| locationFailed | 同样超时，且最近定位请求失败、其后未恢复可信位置 |
| locationServicesDisabled | 系统定位服务关闭 |
| locationPermissionDisabled | 没有始终定位权限 |
| preciseLocationDisabled | 精确位置关闭 |
| backgroundRefreshDisabled | 后台 App 刷新不可用 |

权限/能力异常在获得执行机会时立即记录，不等位置过旧阈值。原因变化更新诊断状态，不为同一未解除周期重复创建短信。普通短暂定位失败不会立即变成“长期无位置”。

在家或时段外会结束位置过旧累计，避免将主动停止连续定位误报为异常；下一时段重新累计。权限异常仍单独保留。需要持续定位时，权限恢复后还要取得新的可信位置才能解除；仅有运动或围栏回家记录不能证明定位权限已恢复。时钟回拨会重置时间基准，避免旧的未来时间无限延迟检查。

## 持久化与后台边界

- JS schema v4，原生 schema v6。升级兼容旧版本；旧原生未发送操作会取消，避免历史测试告警被带入正式模式，历史事件仍保留。
- 检测状态、风险/解除事件、逐联系人通知操作在一次原子写入中保存。写入失败不提前推进检测状态；重启、事件确认消费或重复回调不再次触发同一风险。
- 定位、充电/电量通知、后台刷新状态变化、启动/前台恢复、守护时段边界及系统后台刷新机会都会重新检查。运行中的分钟计时器只补充检查；后台刷新请求还包含约 15 分钟后的电量复查机会。
- 所有请求均受 iOS 调度。系统挂起、关机、强制结束、权限关闭时不保证执行；时间阈值不代表系统会准时唤醒。重启后的文件读取仍需等待首次解锁。

## Mac 和真机验收

在 Mac 恢复本机依赖，使用同一 bundle ID com.llingrui.iamhome 覆盖安装，保留真机旧数据。先运行：

~~~sh
npm run typecheck
npm test
npm run bundle:ios
mise exec -- bundle exec pod install --project-directory=ios
xcodebuild -workspace ios/DaojiaShuoYisheng.xcworkspace \
  -scheme DaojiaShuoYisheng -showdestinations
~~~

从实际列出的模拟器选择 destination，用同一 scheme 执行 test，再构建 Release。该轮新增到 31 项；后续数据管理工作已扩充到 37 项，应运行当前全部测试，详见 [最新验收清单](data-lifecycle-and-place-status.md)。不要用 JS bundle 通过替代 Swift 编译结论。

| 场景 | 验收重点 |
| --- | --- |
| v3/v5 数据升级、旧 1 分钟配置 | 地点/联系人/历史不丢失，测试模式明确，旧待发操作取消 |
| 正式模式前置条件不足 | UI 可解释失败；原生桥直接传入也不能绕过 |
| 两个阈值 1、15、240 及快速连续修改 | 模式限制一致，原生最终值与 UI 相同 |
| 测试告警后切正式，再重启 | 旧告警不外发、不污染新的风险周期 |
| 家外电量 19%、连续回调、未知电量 | 只生成一条；未知值不冒充低电量 |
| 低电量时充电、拔线、回家 | 正确解除、取消操作，再次满足条件才重新触发 |
| 家外位置过旧、定位错误、恢复新位置 | 原因与时间正确，只触发一次，恢复后解除 |
| 关闭/恢复定位、精确位置、后台刷新 | 原因可区分；运动信号不错误解除权限异常 |
| 在家、时段外、跨时段、调整时间/时区 | 不把主动停止采集计为失联；不跨时段累计 |
| 锁屏、系统回收、重启首次解锁 | 风险与操作不重复，记录实际检查机会与延迟 |
| 故障写入、事件确认后重启 | 原子保存、可重试；确认消费不清掉检测去重状态 |
| 诊断报告 | 模式、低电量和位置原因可见；不含号码、短信正文或坐标 |

首次实地只验证本机检测与状态，当前构建不能验证真实 Critical Messaging 发送。
