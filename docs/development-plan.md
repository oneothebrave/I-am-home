# 到家了么开发计划

更新时间：2026-09-21

本计划延续“尽可能不打扰，在后台安静守护”的产品原则。当前优先级先保证纯本机风险检测和恢复可靠，再接入 Apple Critical Messaging；不在界面或说明中暗示家人已经收到通知。

## 已完成的可靠性基础

- [x] 真实位置采点、精度校验和守护地点本地保存
- [x] iOS 原生围栏同步、显著位置变化和地点访问监测
- [x] 单段守护时间限制家外无活动判断
- [x] Core Motion、计步器、地点访问与可信位置位移融合
- [x] 家外无活动事件持久化、恢复、去重和活动解除
- [x] App 重启、定位唤醒、受保护数据恢复和后台刷新请求
- [x] Critical Messaging 操作、收件人和最终短信正文的本地准备
- [x] Critical Messaging 正式发送状态机：逐联系人授权、持久化发送结果、重试、有效期、冷却与风险解除取消
- [x] 快捷指令仅供用户主动测试，不参与风险自动通知
- [x] 守护诊断页面：权限、原生监听、后台恢复、最近信号、风险恢复和通知准备
- [x] 脱敏诊断报告：不包含电话号码、短信正文或经纬度

## P0：Critical Messaging 接入前后必须完成

- [ ] 低电量风险执行器
  - 低于阈值时只生成一次风险
  - 连接充电或电量恢复后解除
  - 在定位唤醒和后台刷新机会中重新检查
  - 生成与无活动风险一致的通知操作
- [ ] 长时间没有可信位置执行器
  - 区分位置过旧、定位失败、权限关闭、精确位置关闭和后台刷新关闭
  - 获得系统执行机会时立即重新判断
  - 不把手机关机或完全离线描述成仍可持续检测
- [x] Critical Messaging 正式发送状态机
  - 收件人授权、准备、发送中、系统接受、失败和受限状态
  - 每位联系人分别持久化结果
  - 重试次数、间隔、有效期和冷却时间
  - 打开 App 不重复发送，风险恢复后不补发过期告警
  - 区分“系统接受发送”和“家人已经收到”
  - 当前安装包仍关闭 capability 构建开关；获得 entitlement 后再做真实发送验证
- [ ] 测试模式与正式模式分离
  - 1 分钟阈值只用于明确的测试模式
  - 测试短信和测试事件显式标注
  - 进入正式模式前检查守护地点、联系人和权限

## P1：上线前质量

- [ ] 完整真机可靠性测试矩阵
  - 锁屏、低电量模式、断网恢复、系统回收、重启首次解锁
  - 用户强制退出 App、跨守护时段、修改时间和时区
  - 围栏边界、定位漂移、权限中途改变
  - Release 构建和最终签名包复测
- [ ] 活动识别实地校准
  - 原地拿起手机、小范围劳动、步行、骑车、坐车和农机振动
  - 位置精度变化和 GPS 跳点
  - 记录误报、漏报及实际活动来源
- [ ] 地点状态稳定性
  - 明确区分地点内、地点附近、地点外和暂时无法确认
  - 围栏边缘增加滞回和防抖验证
- [ ] 老年用户辅助功能
  - 大字体、VoiceOver、高对比度、减少动态效果和触控区域
  - 权限拒绝后的可恢复路径
- [ ] 数据安全与隐私
  - 本地数据保存期限和一键删除
  - 文件保护、备份策略和隐私政策
  - 风险提示不构成医疗诊断

## 需要产品确认后再开发

- [ ] 家中长时间无活动
  - 手机静止不能证明本人静止，不能直接复用家外规则
  - 需要评估 Apple Watch、可穿戴设备或更保守的多信号规则
- [ ] 多段守护时间
  - 当前版本继续保持单段，避免增加设置复杂度
- [ ] 家人端 App 或服务器通知
  - Critical Messaging 路线可用时暂不建设
  - 只有需要通知历史、家庭协作或跨平台时再评估

## 每次发布前的固定检查

- [ ] `npm run typecheck`
- [ ] `npm test`
- [ ] `npm run bundle:ios`
- [ ] iOS 原生 XCTest
- [ ] iPhone Release 覆盖安装，保持 `com.llingrui.iamhome`
- [ ] 核对守护诊断记录与一次完整实地流程
