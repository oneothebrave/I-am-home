# Windows 可靠性、诊断隐私与历史性能加固

更新时间：2026-09-28。项目路径为 `E:\I-am-home`。本轮不开发适老化、不更改风险判定或原生发送能力，不清除真实设备数据。

本文记录上一轮 136 项基线；后续最新 162 项及时间异常期间的保留例外见 [发布防错与时间异常](release-preflight-and-time.md)。

## 原生读取异常恢复

- `getCurrentStatus`、`getPermissions` 增加运行时校验：布尔值不做字符串转换，计数必须为非负安全整数，时间必须有效，权限必须为已知枚举；错误或不完整的必需字段不作为“已就绪”。
- 兼容旧状态接口缺少 `monitoringMode`、`riskHealth`、`reliability`、`dataDeletionPending` 等可选字段；不把缺失值伪装成正式模式或已确认健康。缺少所需原生方法时显示版本不匹配提示。
- 两个只读接口在 JS 获得执行机会时按 8 秒等待上限处理；同类并发请求合并，超时后可重新读取，旧请求迟到的成功/失败不再更新界面。超时不表示取消了原生调用，也不是后台精确定时保证。
- 启动检查未成功前不上传旧配置或自动开启守护；界面提供安全重试。权限刷新失败清除旧权限展示，诊断部分失败不再显示全部刷新成功。
- 守护控制器合并重复刷新；写入后的新刷新不能复用写入前的读取。桥接显式代理原方法，兼容不可枚举/惰性暴露的方法并保留调用上下文。

### 不套用通用超时的范围

开启/暂停、权限申请、配置写入、事件确认和数据清除不因 JS 等待超时而解锁或自动重试。原生写入可能仍在进行，必须保持串行及清除保护。

`getPendingEvents` 内部会刷新持久化队列，`getCriticalMessagingPreparation` 内部会整理通知状态，它们并非无副作用读取，本轮不套用上述超时。当前位置继续使用原生已有采点超时；完整的原生线程阻塞、写入长期不返回、系统权限交互仍需 Mac/iPhone 排查，不宣称所有接口都已具备有界等待。

## 分享诊断的隐私边界

- 分享报告与本机诊断展示分开构建，采用明确字段白名单：只输出已知状态标签、数量、经过格式化的时间及是否存在错误。
- 不导出姓名、地点名称、原始 ID、经纬度、电话号码、短信正文、事件标题/描述、错误正文或未知原因字符串。未知枚举显示“尚未确认”，不回退输出原文。
- 不是通过匹配手机号的正则来“猜测敏感内容”；普通中文短信、变形号码、编码内容和自由文本同样不导出。
- 本机诊断仍可查看原始详情；分享按钮只使用白名单报告，不修改本机记录。报告仍包含时间、活动类别、权限与运行状态，并非完全匿名，只应分享给信任的人。
- 保留“系统已接受发送，不代表送达或已阅读”和测试告警不自动发送的边界；SOS 不因活动或周期重置被报告为已解除。

## 足迹性能与压力回归

- 每页最多渲染 40 条足迹，提供较新、较早和回到最新记录入口；不是不断追加导致最终仍渲染全部记录。
- 查看旧页时以记录 ID 保持位置，新到记录不会把当前页整体推走；锚点被保存期限淘汰后回到最新可用页。空历史不出现空白页或失效的翻页入口。
- 足迹过滤排序及“我的”页数量统计按事件数组记忆，30 秒时钟更新不重排整份足迹。
- 历史保存规则保持不变：普通记录 30 天/2,000 条，活动风险证据等例外仍保留。分页不删除记录、不改变风险状态。

新增自动测试包括：

- 只读格式校验、超时、迟到成功/失败、连续刷新、旧版缺字段与原生方法兼容。
- 整页启动阻断/重试、权限失败/恢复、诊断部分失败，以及未完成清除保持锁定。
- 实际分享按钮与自由文本泄漏回归、未知枚举、长错误文本及 SOS/短信状态文案。
- 2,001 条足迹逐页完整访问，每页最多 40 条；实时新增、历史淘汰与时钟更新。
- 模拟 60 天、7,200 条采样及风险恢复、每周重建 store；8,000 条事件突发时磁盘失败和确认失败后的重启重放；10,000 条活动风险转换的证据保护。
