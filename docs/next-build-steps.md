# 到家了么 - 下一阶段开发步骤

> 2026-09-21：早期 React Native 原型规划已经完成或废弃。当前实现与验证结果以 [重构记录](refactoring.md) 和 [iOS 原生模块说明](ios-native-module.md) 为准。

## 当前基线

- 真实位置采点、精度校验、本地地点保存和 iOS 原生围栏同步已经接通。
- 满足地点与权限条件后自动开始守护；主动暂停意图会持久保存。
- “家外长时间无明显移动”已由原生状态机实现，融合可信位置位移、Core Motion 活动和步数。
- 每日单段守护时间已接入原生检测：时段外清零无活动计时，围栏进出仍全天记录；本版不做分段时段。
- 异常直接生成持久的家人通知事件，不提醒本人，也不提供“我没事”按钮。
- 家外无活动异常落盘后会尝试为第 1 位家人运行短信快捷指令，并单独记录 iOS 是否接受打开请求；锁屏或后台可能被系统拒绝，不能视为自动送达证明。
- 短信快捷指令模板已显式引用系统“快捷指令输入”并关闭“显示编写表单”，收件人和内容直接使用 App 运行时传入的数据；修正模板唯一命名为“到家了么短信通知 V3”，避免运行时命中旧副本。
- 家外无活动异常会原子生成 Critical Messaging 待发送操作，状态页可核对收件人和内容；当前无 entitlement，不会实际发送。

## 下一步

1. 在同一 bundle ID 的真机版本上验证运动权限申请和权限撤回后的状态回读。
2. 分别验证锁屏、App 被系统挂起、设备重启和进程被终止后的计时、事件恢复与快捷指令尝试结果。
3. 在家外进行缩短阈值的受控测试，确认静止只触发一次，移动后可以开启新周期，回家会取消计时。
4. 记录连续定位与 Core Motion 的实际耗电，按真机结果调整采样精度和距离过滤。
5. 开通 Apple Developer Program 后，为同一 bundle ID 配置 Critical Messaging capability、收件人授权和后台发送协调器。
6. 在真机验证守护时段开始、结束、修改时段及系统时区变化后的原生状态切换。

## 验收边界

检测器和通知送达器是两个独立环节。当前阶段可以证明异常在本机被识别、持久保存并进入家人通知队列，但尚不能证明短信、电话或其他外部通知已自动送达。
